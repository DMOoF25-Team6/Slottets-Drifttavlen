## Purpose

This document defines the marks used in `uc-005.dcd.pim-marked.puml`. Marks are **abstract transformation hints** added to PIM elements to guide the PIM-to-PSM transformation.

A mark says **what kind** of transformation is needed. The PIM-to-PSM mapping document specifies **exactly how** each mark is realized on a specific platform.

---

## Persistence Marks

| Mark | Meaning |
|------|---------|
| `<<Persistent>>` | Element must survive across system restarts |
| `<<UniquelyIdentified>>` | Element has identity distinct from its values |
| `<<ImmutableSet>>` | Element belongs to a fixed, predefined set |
| `<<Auditable>>` | Changes must be traceable over time |
| `<<PersistedAsText>>` | When stored, use textual form (for enumerations) |

## Behavioral Marks

| Mark | Meaning |
|------|---------|
| `<<LayeredResponsibility>>` | Element decomposes into architectural layers when transformed |
| `<<RestExposed>>` | Operation crosses a network boundary (remote access) |
| `<<QueryOperation>>` | Read-only, idempotent, no state change |
| `<<CommandOperation>>` | Modifies system state |
| `<<PeriodicallyExecuted>>` | Runs at regular intervals (timer-driven) |

---

## What These Marks Deliberately Do NOT Specify

- **No platform names** — `<<Persistent>>`, not `<<EFCoreEntity>>`
- **No technology paths** — no concrete URLs
- **No concrete numbers** — no `MaxLength=100`, no `60s`
- **No framework specifics** — no `DbContext`, no `Spring`
- **No HTTP verbs** — no `HttpGet`, no `HttpPost`

All of those belong in the PSM. Marks here express the **transformation category**, not the concrete realization.

---

## Marks vs Mappings vs PSM

| Layer | What it contains |
|-------|------------------|
| **Marks (this document)** | Abstract categories: "this element is persistent" |
| **PIM-to-PSM mapping** | Rules: "`<<Persistent>>` → C# class with `[Key]` attribute on identifier" |
| **PSM** | Realization: `public class PhoneAssignment { [Key] public Guid Id { get; set; } }` |

---

## Multiple Platforms, Same Marks

The same marked PIM can produce multiple PSMs depending on which mapping is applied:

| Mark | .NET 8 mapping | Java Spring mapping | Python Flask mapping |
|------|----------------|---------------------|----------------------|
| `<<Persistent>>` | EF Core entity, `[Key]`, `DbSet<T>` | `@Entity`, `@Id`, JPA Repository | SQLAlchemy `db.Model` |
| `<<RestExposed>>` | ASP.NET Core Controller | Spring `@RestController` | Flask `@app.route` |
| `<<QueryOperation>>` | `HttpGet` action | `@GetMapping` | `methods=['GET']` |
| `<<CommandOperation>>` | `HttpPost` / `HttpDelete` | `@PostMapping` / `@DeleteMapping` | `methods=['POST'/'DELETE']` |

This is the **core MDA promise**: one PIM, many PSMs.

## Maintenance

- Add new marks here when needed by the PIM
- Marks must remain abstract (no platform names)
- Each mark must have a corresponding rule in the PIM-to-PSM mapping
