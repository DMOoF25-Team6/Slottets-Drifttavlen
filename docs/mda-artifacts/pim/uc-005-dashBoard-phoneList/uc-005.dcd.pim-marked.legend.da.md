## Formål

Dette dokument definerer markene brugt i `uc-005.dcd.pim-marked.da.puml`. Marks er **abstrakte transformations-hints** tilføjet til PIM-elementer for at vejlede PIM-til-PSM-transformationen.

En mark fortæller **hvilken slags** transformation der er nødvendig. PIM-til-PSM mapping-dokumentet specificerer **præcist hvordan** hver mark realiseres på en specifik platform.

---

## Persistens-marks

| Mark | Betydning |
|------|-----------|
| `<<Persistent>>` | Element skal overleve systemgenstart |
| `<<UniquelyIdentified>>` | Element har identitet adskilt fra sine værdier |
| `<<ImmutableSet>>` | Element tilhører et fast, foruddefineret sæt |
| `<<Auditable>>` | Ændringer skal kunne spores over tid |
| `<<PersistedAsText>>` | Ved lagring: brug tekstform (til enumerationer) |

## Adfærds-marks

| Mark | Betydning |
|------|-----------|
| `<<LayeredResponsibility>>` | Element nedbrydes i arkitektoniske lag ved transformation |
| `<<RestExposed>>` | Operation krydser en netværksgrænse (fjernadgang) |
| `<<QueryOperation>>` | Læser kun, idempotent, ingen tilstandsændring |
| `<<CommandOperation>>` | Modificerer systemtilstand |
| `<<PeriodicallyExecuted>>` | Kører ved regelmæssige intervaller (timer-styret) |

---

## Hvad disse marks bevidst IKKE specificerer

- **Ingen platform-navne** — `<<Persistent>>`, ikke `<<EFCoreEntity>>`
- **Ingen teknologi-stier** — ingen konkrete URL'er
- **Ingen konkrete tal** — ingen `MaxLength=100`, ingen `60s`
- **Ingen framework-detaljer** — ingen `DbContext`, ingen `Spring`
- **Ingen HTTP-verber** — ingen `HttpGet`, ingen `HttpPost`

Alt det hører til PSM. Marks her udtrykker **transformationskategorien**, ikke den konkrete realisering.

---

## Marks vs Mappings vs PSM

| Lag | Hvad det indeholder |
|-----|---------------------|
| **Marks (dette dokument)** | Abstrakte kategorier: "dette element er persistent" |
| **PIM-til-PSM mapping** | Regler: "`<<Persistent>>` → C# klasse med `[Key]`-attribut på identifier" |
| **PSM** | Realisering: `public class PhoneAssignment { [Key] public Guid Id { get; set; } }` |

---

## Flere platforme, samme marks

Samme markerede PIM kan producere flere PSM'er afhængigt af hvilken mapping der anvendes:

| Mark | .NET 8 mapping | Java Spring mapping | Python Flask mapping |
|------|----------------|---------------------|----------------------|
| `<<Persistent>>` | EF Core entitet, `[Key]`, `DbSet<T>` | `@Entity`, `@Id`, JPA Repository | SQLAlchemy `db.Model` |
| `<<RestExposed>>` | ASP.NET Core Controller | Spring `@RestController` | Flask `@app.route` |
| `<<QueryOperation>>` | `HttpGet` action | `@GetMapping` | `methods=['GET']` |
| `<<CommandOperation>>` | `HttpPost` / `HttpDelete` | `@PostMapping` / `@DeleteMapping` | `methods=['POST'/'DELETE']` |

Dette er **kernen i MDA-løftet**: én PIM, mange PSM'er.

---

## Vedligeholdelse

- Tilføj nye marks her når PIM kræver det
- Marks skal forblive abstrakte (ingen platform-navne)
- Hver mark skal have en tilsvarende regel i PIM-til-PSM mappingen
