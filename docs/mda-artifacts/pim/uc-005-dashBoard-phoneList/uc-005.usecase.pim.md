## Use Case

**Name:** Coordinate Phone Assignments for a Shift

**Primary Actor:** Caregiver (system role)

**Supporting Actors:**
- Shift Coordinator (system role)
- System Time Event (introduced by Rule M1)

**Scope:** Phone coordination system

**Level:** User goal

---

## Stakeholders and Interests (PIM-level)

| Stakeholder | Interest at system level |
|-------------|--------------------------|
| Caregiver | Quickly see and update phone assignments for the current shift |
| Shift Coordinator | Reliable overview that reflects current state |
| Slottet management | System enforces business rules consistently |
| Other connected use cases | Phone assignment data is queryable by other system parts |

---

## Preconditions

- The system holds the fixed set of work phones for Slottet.
- A current shift is identifiable (Day, Evening, or Night).
- The actor has been authenticated (handled by UC-004 Login).

## Postconditions

**Success guarantee:**
- The system has persisted the phone-to-caregiver assignment for the selected shift.
- The assignment is visible to other actors querying the system for the same shift.

**Minimal guarantee:**
- The system state is consistent: either the assignment is recorded, or the previous state is preserved with no partial update.

---

## Main Flow: View Phone List for Active Shift

1. Caregiver requests the phone list for the active shift.
2. System retrieves all phone assignments for the active shift.
3. System returns the list of phones with current assignments.

## Main Flow: Assign Caregiver Name to Phone

1. Caregiver selects a shift type.
2. System retrieves phone assignments for the selected shift.
3. Caregiver provides their name and selects a phone number.
4. System validates that the shift is selected and the phone exists.
5. System records the assignment (phone + caregiver name + shift).
6. System confirms the assignment is persisted.

## Main Flow: Clear Assignment

1. Caregiver selects a phone with an existing assignment for the selected shift.
2. Caregiver indicates the assignment should be removed.
3. System validates the request.
4. System marks the phone as unassigned for the selected shift.
5. System confirms the change.

## Separate Flow: Automatic Refresh (System Time Event)

1. System Time Event occurs.
2. System retrieves current phone assignments for the active shift.
3. System makes the updated assignments available to subscribers.

---

## Alternative Flows

**3a. Shift type not selected (Assign Caregiver Name):**
- 1. System rejects the assignment request.
- 2. System returns an indication that a shift type is required.

**5a. Assignment conflicts with business rules (Assign Caregiver Name):**
- 1. System detects that another assignment violates a business rule (e.g. same caregiver already assigned to another phone on same shift).
- 2. System rejects the assignment with a rule violation indication.

**5b. Persistence fails (Assign Caregiver Name):**
- 1. System cannot complete the persist operation.
- 2. System reports failure to the caregiver.
- 3. System preserves the previous state.

---

## Business Rules (from CIM, applied as system constraints — Rule M5)

| Rule | System enforcement |
|------|-------------------|
| One caregiver per phone per shift | System rejects assignment if phone already has a caregiver for the shift |
| One phone per caregiver per shift | System rejects assignment if caregiver already has a phone for the shift |
| Fixed phone numbers | System validates that the phone number belongs to the configured set |
| Shift types are Day/Evening/Night | System validates that shift type is one of the closed enumeration |
| Assignments are per shift | System does not propagate assignments across shifts |

---

## System Responsibilities (PIM-level)

The system must:

- **Identify** the active shift (based on time or explicit selection)
- **Store** phone-to-caregiver assignments per shift
- **Retrieve** phone assignments for a given shift
- **Validate** assignment requests against business rules
- **Update** assignments when caregivers make changes
- **Notify** interested parties when assignments change (e.g. via Time Event refresh)

The system must NOT:

- Make calls or send messages on behalf of the phones
- Propagate assignments outside the scope of a single shift
- Allow assignments that violate business rules
