## Formål

Dette dokument specificerer **transformationsreglerne** for at konvertere den markerede Platform Independent Model (PIM) af UC-005 til en Platform Specific Model (PSM) for .NET 8 / EF Core / MySQL / Clean Architecture-målplatformen.

Hver regel tager en mark fra `uc-005.dcd.pim-marked.da.puml` og specificerer de konkrete PSM-artefakter den producerer.

I en fuldautomatisk MDA-værktøjskæde ville disse regler blive udført af en transformations-motor. I dette projekt er de dokumenteret manuelt som **sporbarhedsbevis** og anvendes i hånden når PSM skrives.

---

## Transformationsfilosofi

PIM → PSM er trinet hvor **teknologibeslutninger træffes**:

| Aspekt | PIM | PSM |
|--------|-----|-----|
| Persistens | "Skal overleve genstart" | EF Core-entitet med `[Key]` + `DbSet<T>` i `AppDbContext` |
| Netværks-eksponering | "Krydser netværksgrænse" | ASP.NET Core Controller med HTTP-attribut |
| Tilstandsændring | "Modificerer tilstand" | `HttpPost` eller `HttpDelete` |
| Read-only | "Idempotent forespørgsel" | `HttpGet` |
| Identitet | "Har identitet" | `Guid` primærnøgle |
| Typesystem | Generisk (`UUID`, `String`) | Konkret (`Guid`, `string`) |

PIM'en bevares; PSM'en udledes fra PIM + marks + disse regler.

---

## Typemappings (Generisk → .NET)

Disse regler anvendes automatisk hvor som helst de listede PIM-typer optræder:

| PIM-type | PSM-type (.NET 8) | Bemærkninger |
|----------|-------------------|--------------|
| `UUID` | `Guid` | Native .NET globally unique identifier |
| `String` | `string` | UTF-16 referencetype |
| `DateTime` | `DateTime` | Genbruget navn, .NET-semantik |
| `List<T>` | `IEnumerable<T>` til forespørgsler, `T[]` til resultater | Async wrap nedenfor |
| `void` | `Task` (til async) | Async-by-default i PSM |
| `T` (returværdi) | `Task<T>` | Async-by-default i PSM |
| `enum` | C# `enum` med `[Column(TypeName = "varchar")]` når markeret `<<PersistedAsText>>` | |

## Mark-transformationsregler

### Regel T1: `<<Persistent>>` → EF Core-entitet

**Kilde-mark:** `<<Persistent>>` på en klasse

**PSM-artefakter produceret:**

1. **Domæne-entitet** (`src/Domain/Entities/<KlasseNavn>.cs`):
   ```csharp
   public class PhoneAssignment : IEntity
   {
       public Guid Id { get; set; }
       // ... andre egenskaber
   }
   ```

2. **DbSet-registrering** (`src/Infrastructure.Data/AppDbContext.cs`):
   ```csharp
   public DbSet<PhoneAssignment> PhoneAssignments { get; set; }
   ```

3. **EF Core-konfiguration** (`src/Infrastructure.Data/Configurations/<KlasseNavn>Configuration.cs`):
   ```csharp
   public class PhoneAssignmentConfiguration : IEntityTypeConfiguration<PhoneAssignment>
   {
       public void Configure(EntityTypeBuilder<PhoneAssignment> builder) { /* ... */ }
   }
   ```

**Validering:** Hver PIM-klasse markeret `<<Persistent>>` skal optræde i `AppDbContext` som `DbSet<T>`.

---

### Regel T2: `<<UniquelyIdentified>>` + `<<Identifier>>` → Primærnøgle

**Kilde-marks:** `<<UniquelyIdentified>>` på en klasse og `<<Identifier>>` på dens egenskab

**PSM-artefakter produceret:**

```csharp
public class PhoneAssignment : IEntity
{
    [Key]
    public Guid Id { get; set; }
    // ...
}
```

`[Key]`-data annotation tilføjes. EF Core genererer en primærnøgle-kolonne.

**Validering:** Hver `<<UniquelyIdentified>>`-klasse har præcis én `[Key]`-annoteret egenskab.

---

### Regel T3: `<<RequiredValue>>` → `[Required]`-attribut

**Kilde-mark:** `<<RequiredValue>>` på en egenskab

**PSM-artefakt:**

```csharp
[Required]
public string FirstName { get; set; }
```

EF Core genererer en `NOT NULL`-begrænsning på kolonnen.

---

### Regel T4: `<<BoundedLength>>` → `[MaxLength(N)]`-attribut

**Kilde-mark:** `<<BoundedLength>>` på en string-egenskab

**PSM-artefakt (med konkret længde besluttet her):**

```csharp
[Required]
[MaxLength(100)]   // FirstName, LastName
[MaxLength(10)]    // Phone.Number (telefonformat)
public string FirstName { get; set; }
```

**Beslutnings-begrundelse:**

| Egenskab | MaxLength | Hvorfor |
|----------|-----------|---------|
| `Caregiver.FirstName` | 100 | Standard navnefelt-længde |
| `Caregiver.LastName` | 100 | Standard navnefelt-længde |
| `Phone.Number` | 10 | Slottets telefonnumre er 5 cifre, tillad 10 for fremtidig fleksibilitet |

**Vigtigt:** De konkrete tal (100, 10) besluttes HER, i mappingen. PIM siger kun "bounded" — den siger ikke "100".

---

### Regel T5: `<<UniquePerCombination>>` → Sammensat unikt indeks

**Kilde-mark:** `<<UniquePerCombination>>` på en klasse (typisk på en association)

**PSM-artefakt (Fluent API i EntityTypeConfiguration):**

```csharp
public void Configure(EntityTypeBuilder<PhoneAssignment> builder)
{
    builder.HasIndex(pa => new { pa.PhoneNumber, pa.ShiftType })
           .IsUnique()
           .HasDatabaseName("IX_PhoneAssignment_Phone_Shift");

    builder.HasIndex(pa => new { pa.CaregiverId, pa.ShiftType })
           .IsUnique()
           .HasDatabaseName("IX_PhoneAssignment_Caregiver_Shift");
}
```

To sammensatte unikke indekser håndhæver forretningsreglerne fra CIM Regel M5.

---

### Regel T6: `<<Auditable>>` → Tidsstempler + Audit-log

**Kilde-mark:** `<<Auditable>>` på en klasse

**PSM-artefakter:**

1. Tilføj tidsstempler til entiteten:
   ```csharp
   public DateTime AssignedAt { get; set; }
   public DateTime? ModifiedAt { get; set; }
   public string? ModifiedBy { get; set; }
   ```

2. Hook ind i `AppDbContext.SaveChangesAsync()` for at opdatere `ModifiedAt`/`ModifiedBy` automatisk.

3. (Valgfrit) Tilføj audit-log-tabel for fuld historik.

For UC-005 anvender vi kun tidsstempel-tilgangen (audit-loggen er en fremtidig udvidelse).

### Regel T7: `<<ImmutableSet>>` → Seed-data

**Kilde-mark:** `<<ImmutableSet>>` på en klasse

**PSM-artefakt (i EF Core-migration eller seeding):**

```csharp
modelBuilder.Entity<Phone>().HasData(
    new Phone { Number = "41522" },

    new Phone { Number = "41527" },
    new Phone { Number = "41529" }

```

Det faste sæt fra CIM bliver til seed-data i databasen.

### Regel T8: `<<PersistedAsText>>` → varchar-kolonne til enum

**Kilde-mark:** `<<PersistedAsText>>` på en enumeration

**PSM-artefakt:**

```csharp
public class PhoneAssignment
{
    [Column(TypeName = "varchar(10)")]
    public ShiftType ShiftType { get; set; }
}
```

Eller via Fluent API:

```csharp
builder.Property(pa => pa.ShiftType)
       .HasConversion<string>()
       .HasMaxLength(10);
```

Dette undgår at gemme magiske tal i databasen; værdierne "Day", "Evening", "Night" optræder som tekst.

---

### Regel T9: `<<ReferencedEntity>>` → Fremmednøgle-relation

**Kilde-mark:** `<<ReferencedEntity>>` på en association

**PSM-artefakter:**

1. Fremmednøgle-egenskab på den afhængige entitet:
   ```csharp
   public Guid CaregiverId { get; set; }
   public Caregiver Caregiver { get; set; }
   ```

2. Fluent API-relations-konfig:
   ```csharp
   builder.HasOne(pa => pa.Caregiver)
          .WithMany()
          .HasForeignKey(pa => pa.CaregiverId)
          .OnDelete(DeleteBehavior.Restrict);
   ```

### Regel T10: `<<LayeredResponsibility>>` → Clean Architecture-nedbrydning

**Kilde-mark:** `<<LayeredResponsibility>>` på systemklassen

**PSM-artefakter produceret** — systemklassen nedbrydes i en 7-klasse-kæde:

```
WebApi.PhoneAssignmentsController
  └─→ Core.IPhoneAssignmentService                (interface)
        └─→ Core.PhoneAssignmentService           (implementering)
              └─→ Core.IPhoneAssignmentManager    (interface)
                    └─→ Infrastructure.PhoneAssignmentManager   (impl)
                          └─→ Core.IPhoneAssignmentRepository   (interface)
                                └─→ Infrastructure.Data.PhoneAssignmentRepository (impl)
```

Hvert lag har et specifikt ansvar:

| Lag | Ansvar | Projekt |
|-----|--------|---------|
| Controller | HTTP-routing, model-binding, statuskoder | `src/Api` |
| Service | Applikationslogik, orkestrering | `src/Core` |
| Manager | Infrastruktur-abstraktion, eksterne kald | `src/Infrastructure` |
| Repository | Dataadgang, EF Core-forespørgsler | `src/Infrastructure.Data` |

Interfaces lever i `Core` for dependency inversion. Implementeringer lever i `Infrastructure` og `Infrastructure.Data`.

### Regel T12: `<<QueryOperation>>` → `HttpGet`-action

**Kilde-mark:** `<<QueryOperation>>` på en operation

**PSM-artefakt (med konkret URL-mønster besluttet her):**

| PIM-operation | HTTP-verb | URL-mønster |
|---------------|-----------|-------------|
| `hentTelefonlisteForAktivVagt()` | GET | `/api/phone-assignments/active` |
| `vælgVagt(vagttype)` | GET | `/api/phone-assignments/by-shift/{shiftType}` |

Eksempel:

```csharp
[HttpGet("active")]
public async Task<ActionResult<PhoneAssignmentDto[]>> GetActive(CancellationToken ct)
{
    var result = await _service.GetCurrentPhoneAssignmentsForActiveShiftAsync(ct);
    return Ok(result);
}
```

### Regel T13: `<<CommandOperation>>` → `HttpPost`/`HttpDelete`-action

**Kilde-mark:** `<<CommandOperation>>` på en operation

**PSM-artefakt (konkret verb besluttet af operations-semantik):**

| PIM-operation | HTTP-verb | Begrundelse |
|---------------|-----------|-------------|
| `tildelTelefon(...)` | POST | Opretter en ny ressource |
| `rydTildeling(...)` | DELETE | Fjerner en ressource |

```csharp
[HttpPost]
public async Task<ActionResult<PhoneAssignmentDto>> Assign(
    [FromBody] AssignPhoneRequest request,
    CancellationToken ct)
{
    var result = await _service.AssignPhoneAsync(request, ct);
    return Ok(result);
}

[HttpDelete("{phoneNumber}/{shiftType}")]
public async Task<IActionResult> Clear(string phoneNumber, ShiftType shiftType, CancellationToken ct)
{
    await _service.ClearAssignmentAsync(phoneNumber, shiftType, ct);
    return NoContent();
}
```

### Regel T14: `<<PeriodicallyExecuted>>` → Hosted Service

**Kilde-mark:** `<<PeriodicallyExecuted>>` på en operation

**PSM-artefakt (konkret interval besluttet her):**

| PIM-operation | Interval | Hosting-model |
|---------------|----------|---------------|
| `opdaterTelefonliste()` | 60 sekunder | `IHostedService` baggrundsservice |

```csharp
public class PhoneListRefreshService : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly TimeSpan _interval = TimeSpan.FromSeconds(60);

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            using var scope = _scopeFactory.CreateScope();
            var service = scope.ServiceProvider.GetRequiredService<IPhoneAssignmentService>();
            await service.RefreshAsync(stoppingToken);
            await Task.Delay(_interval, stoppingToken);
        }
    }
}
```

**60-sekunders intervallet besluttes HER i mappingen** — PIM markerer kun operationen som periodisk.

## Yderligere PSM-artefakter (ud over marks)

Nogle PSM-elementer introduceres pga. platform-konventioner, ikke direkte fra PIM-marks:

| PSM-artefakt | Begrundelse for eksistens |
|--------------|---------------------------|
| `PhoneAssignmentDto` | Clean Architecture forbyder at eksponere domæne-entiteter på tværs af lag-grænser |
| `PhoneAssignmentMapper` | Konvertering mellem entitet og DTO |
| `IPhoneAssignmentRepository`-interface | Dependency Inversion Principle (SOLID) for testbarhed |
| `IPhoneAssignmentService`-interface | Samme: muliggør mocking i tests |
| `IPhoneAssignmentManager`-interface | Samme: adskiller infrastruktur-abstraktion |

Disse er **platform-konventioner** anvendt under transformation, ikke strenge mark→PSM-mappings. En anden målplatform (fx Python Flask) ville måske slet ikke have brug for DTO'er.

## Valideringstjekliste

Efter anvendelse af alle regler skal den resulterende PSM opfylde:

- [ ] Hver `<<Persistent>>` PIM-klasse har et `DbSet<T>` i `AppDbContext`
- [ ] Hver `<<UniquelyIdentified>>`-klasse har præcis én `[Key]`-egenskab
- [ ] Hver `<<RequiredValue>>`-egenskab har `[Required]`
- [ ] Hver `<<BoundedLength>>`-egenskab har `[MaxLength(N)]` med konkret N
- [ ] Hver `<<UniquePerCombination>>` har et sammensat unikt indeks
- [ ] Hver `<<ImmutableSet>>` er seeded i migrations
- [ ] Hver `<<PersistedAsText>>` enum bruger string-konvertering
- [ ] Hver `<<LayeredResponsibility>>`-systemklasse har en 4-lags-kæde (Controller → Service → Manager → Repository) med DI-interfaces i `Core`
- [ ] Hver `<<RestExposed>>`-operation har en tilsvarende controller-action
- [ ] Hver `<<QueryOperation>>` bruger `[HttpGet]`
- [ ] Hver `<<CommandOperation>>` bruger `[HttpPost]` eller `[HttpDelete]`
- [ ] Hver `<<PeriodicallyExecuted>>`-operation kører i en `IHostedService`
