## Purpose

This document specifies the **transformation rules** for converting the marked Platform Independent Model (PIM) of UC-005 into a Platform Specific Model (PSM) for the .NET 8 / EF Core / MySQL / Clean Architecture target platform.

Each rule takes a mark from `uc-005.dcd.pim-marked.puml` and specifies the concrete PSM artifacts it produces.

In a fully automated MDA toolchain, these rules would be executed by a transformation engine. In this project they are documented manually as **traceability evidence** and applied by hand when writing the PSM.

---

## Transformation Philosophy

PIM → PSM is the step where **technology decisions are made**:

| Aspect | PIM | PSM |
|--------|-----|-----|
| Persistence | "Must survive restart" | EF Core entity with `[Key]` + `DbSet<T>` in `AppDbContext` |
| Network exposure | "Crosses network boundary" | ASP.NET Core Controller with HTTP attribute |
| State change | "Modifies state" | `HttpPost` or `HttpDelete` |
| Read-only | "Idempotent query" | `HttpGet` |
| Identity | "Has identity" | `Guid` primary key |
| Type system | Generic (`UUID`, `String`) | Concrete (`Guid`, `string`) |

The PIM is preserved; the PSM is derived from PIM + marks + these rules.

---

## Type Mappings (Generic → .NET)

These rules apply automatically wherever the listed PIM types appear:

| PIM Type | PSM Type (.NET 8) | Notes |
|----------|-------------------|-------|
| `UUID` | `Guid` | Native .NET globally unique identifier |
| `String` | `string` | UTF-16 reference type |
| `DateTime` | `DateTime` | Reused name, .NET semantics |
| `List<T>` | `IEnumerable<T>` for queries, `T[]` for results | Async wraps below |
| `void` | `Task` (for async) | Async-by-default in PSM |
| `T` (return) | `Task<T>` | Async-by-default in PSM |
| `enum` | C# `enum` with `[Column(TypeName = "varchar")]` when marked `<<PersistedAsText>>` | |

## Mark Transformation Rules

### Rule T1: `<<Persistent>>` → EF Core Entity

**Source mark:** `<<Persistent>>` on a class

**PSM artifacts produced:**

1. **Domain entity** (`src/Domain/Entities/<ClassName>.cs`):
   ```csharp
   public class PhoneAssignment : IEntity
   {
       public Guid Id { get; set; }
       // ... other properties
   }
   ```

2. **DbSet registration** (`src/Infrastructure.Data/AppDbContext.cs`):
   ```csharp
   public DbSet<PhoneAssignment> PhoneAssignments { get; set; }
   ```

3. **EF Core configuration** (`src/Infrastructure.Data/Configurations/<ClassName>Configuration.cs`):
   ```csharp
   public class PhoneAssignmentConfiguration : IEntityTypeConfiguration<PhoneAssignment>
   {
       public void Configure(EntityTypeBuilder<PhoneAssignment> builder) { /* ... */ }
   }
   ```

**Validation:** Every PIM class marked `<<Persistent>>` must appear in `AppDbContext` as a `DbSet<T>`.

---

### Rule T2: `<<UniquelyIdentified>>` + `<<Identifier>>` → Primary Key

**Source marks:** `<<UniquelyIdentified>>` on a class and `<<Identifier>>` on its property

**PSM artifacts produced:**

```csharp
public class PhoneAssignment : IEntity
{
    [Key]
    public Guid Id { get; set; }
    // ...
}
```

The `[Key]` data annotation is added. EF Core generates a primary key column.

**Validation:** Every `<<UniquelyIdentified>>` class has exactly one `[Key]`-annotated property.

---

### Rule T3: `<<RequiredValue>>` → `[Required]` Attribute

**Source mark:** `<<RequiredValue>>` on a property

**PSM artifact:**

```csharp
[Required]
public string FirstName { get; set; }
```

EF Core generates a `NOT NULL` constraint on the column.

---

### Rule T4: `<<BoundedLength>>` → `[MaxLength(N)]` Attribute

**Source mark:** `<<BoundedLength>>` on a string property

**PSM artifact (with concrete length decided here):**

```csharp
[Required]
[MaxLength(100)]   // FirstName, LastName
[MaxLength(10)]    // Phone.Number (phone format)
public string FirstName { get; set; }
```

**Decision rationale:**

| Property | MaxLength | Why |
|----------|-----------|-----|
| `Caregiver.FirstName` | 100 | Standard name field length |
| `Caregiver.LastName` | 100 | Standard name field length |
| `Phone.Number` | 10 | Slottet phone numbers are 5 digits, allow 10 for future flexibility |

**Important:** The concrete numbers (100, 10) are decided HERE, in the mapping. The PIM only says "bounded" — it does not say "100".

---

### Rule T5: `<<UniquePerCombination>>` → Composite Unique Index

**Source mark:** `<<UniquePerCombination>>` on a class (typically on an association)

**PSM artifact (Fluent API in EntityTypeConfiguration):**

```csharp
public void Configure(EntityTypeBuilder<PhoneAssignment> builder)
{
    builder.HasIndex(pa => new { pa.PhoneNumber, pa.ShiftType })
           .IsUnique()
           .HasDatabaseName("IX_PhoneAssignment_Phone_Shift");

    builder.HasIndex(pa => new { pa.CaregiverId, pa.ShiftType })
           .IsUnique()
           .HasDatabaseName("IX_PhoneAssignment_Caregiver_Shift");
}
```

Two composite unique indexes enforce the business rules from CIM Rule M5.

---

### Rule T6: `<<Auditable>>` → Timestamps + Audit Log

**Source mark:** `<<Auditable>>` on a class

**PSM artifacts:**

1. Add timestamps to the entity:
   ```csharp
   public DateTime AssignedAt { get; set; }
   public DateTime? ModifiedAt { get; set; }
   public string? ModifiedBy { get; set; }
   ```

2. Hook into `AppDbContext.SaveChangesAsync()` to update `ModifiedAt`/`ModifiedBy` automatically.

3. (Optional) Add audit log table for full history.

For UC-005 we apply only the timestamp approach (the audit log is a future enhancement).

### Rule T7: `<<ImmutableSet>>` → Seed Data

**Source mark:** `<<ImmutableSet>>` on a class

**PSM artifact (in EF Core migration or seeding):**


The fixed set from CIM becomes seed data in the database.

### Rule T8: `<<PersistedAsText>>` → varchar Column for Enum

**Source mark:** `<<PersistedAsText>>` on an enumeration

**PSM artifact:**

```csharp
public class PhoneAssignment
{
    [Column(TypeName = "varchar(10)")]
    public ShiftType ShiftType { get; set; }
}
```

Or via Fluent API:

```csharp
builder.Property(pa => pa.ShiftType)
       .HasConversion<string>()
       .HasMaxLength(10);
```

This avoids storing magic numbers in the database; the values "Day", "Evening", "Night" appear as text.

---

### Rule T9: `<<ReferencedEntity>>` → Foreign Key Relationship

**Source mark:** `<<ReferencedEntity>>` on an association

**PSM artifacts:**

1. Foreign key property on the dependent entity:
   ```csharp
   public Guid CaregiverId { get; set; }
   public Caregiver Caregiver { get; set; }
   ```

2. Fluent API relationship config:
   ```csharp
   builder.HasOne(pa => pa.Caregiver)
          .WithMany()
          .HasForeignKey(pa => pa.CaregiverId)
          .OnDelete(DeleteBehavior.Restrict);
   ```

---

### Rule T10: `<<LayeredResponsibility>>` → Clean Architecture Decomposition

**Source mark:** `<<LayeredResponsibility>>` on the system class

**PSM artifacts produced** — the system class decomposes into a 7-class chain:

```
WebApi.PhoneAssignmentsController
  └─→ Core.IPhoneAssignmentService                (interface)
        └─→ Core.PhoneAssignmentService           (implementation)
              └─→ Core.IPhoneAssignmentManager    (interface)
                    └─→ Infrastructure.PhoneAssignmentManager   (impl)
                          └─→ Core.IPhoneAssignmentRepository   (interface)
                                └─→ Infrastructure.Data.PhoneAssignmentRepository (impl)
```

Each layer has a specific responsibility:

| Layer | Responsibility | Project |
|-------|---------------|---------|
| Controller | HTTP routing, model binding, status codes | `src/Api` |
| Service | Application logic, orchestration | `src/Core` |
| Manager | Infrastructure abstraction, external calls | `src/Infrastructure` |
| Repository | Data access, EF Core queries | `src/Infrastructure.Data` |

Interfaces live in `Core` for dependency inversion. Implementations live in `Infrastructure` and `Infrastructure.Data`.

### Rule T12: `<<QueryOperation>>` → `HttpGet` Action

**Source mark:** `<<QueryOperation>>` on an operation

**PSM artifact (with concrete URL pattern decided here):**

| PIM operation | HTTP verb | URL pattern |
|---------------|-----------|-------------|
| `getPhoneListForActiveShift()` | GET | `/api/phone-assignments/active` |
| `selectShift(shiftType)` | GET | `/api/phone-assignments/by-shift/{shiftType}` |

Example:

```csharp
[HttpGet("active")]
public async Task<ActionResult<PhoneAssignmentDto[]>> GetActive(CancellationToken ct)
{
    var result = await _service.GetCurrentPhoneAssignmentsForActiveShiftAsync(ct);
    return Ok(result);
}
```

### Rule T13: `<<CommandOperation>>` → `HttpPost`/`HttpDelete` Action

**Source mark:** `<<CommandOperation>>` on an operation

**PSM artifact (concrete verb decided by operation semantics):**

| PIM operation | HTTP verb | Rationale |
|---------------|-----------|-----------|
| `assignPhone(...)` | POST | Creates a new resource |
| `clearAssignment(...)` | DELETE | Removes a resource |

```csharp
[HttpPost]
public async Task<ActionResult<PhoneAssignmentDto>> Assign(
    [FromBody] AssignPhoneRequest request,
    CancellationToken ct)
{
    var result = await _service.AssignPhoneAsync(request, ct);
    return Ok(result);
}

[HttpDelete("{phoneNumber}/{shiftType}")]
public async Task<IActionResult> Clear(string phoneNumber, ShiftType shiftType, CancellationToken ct)
{
    await _service.ClearAssignmentAsync(phoneNumber, shiftType, ct);
    return NoContent();
}
```

### Rule T14: `<<PeriodicallyExecuted>>` → Hosted Service

**Source mark:** `<<PeriodicallyExecuted>>` on an operation

**PSM artifact (concrete interval decided here):**

| PIM operation | Interval | Hosting model |
|---------------|----------|---------------|
| `refreshPhoneList()` | 60 seconds | `IHostedService` background worker |

```csharp
public class PhoneListRefreshService : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly TimeSpan _interval = TimeSpan.FromSeconds(60);

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            using var scope = _scopeFactory.CreateScope();
            var service = scope.ServiceProvider.GetRequiredService<IPhoneAssignmentService>();
            await service.RefreshAsync(stoppingToken);
            await Task.Delay(_interval, stoppingToken);
        }
    }
}
```

**The 60-second interval is decided HERE in the mapping** — the PIM only marks the operation as periodic.

## Additional PSM Artifacts (Beyond Marks)

Some PSM elements are introduced because of platform conventions, not directly from PIM marks:

| PSM artifact | Reason for existence |
|--------------|---------------------|
| `PhoneAssignmentDto` | Clean Architecture forbids exposing domain entities across layer boundaries |
| `PhoneAssignmentMapper` | Conversion between entity and DTO |
| `IPhoneAssignmentRepository` interface | Dependency Inversion Principle (SOLID) for testability |
| `IPhoneAssignmentService` interface | Same: enables mocking in tests |
| `IPhoneAssignmentManager` interface | Same: separates infrastructure abstraction |

These are **platform conventions** applied during transformation, not strict mark→PSM mappings. A different target platform (e.g. Python Flask) might not need DTOs at all.

## Validation Checklist

After applying all rules, the resulting PSM should satisfy:

- [ ] Every `<<Persistent>>` PIM class has a `DbSet<T>` in `AppDbContext`
- [ ] Every `<<UniquelyIdentified>>` class has exactly one `[Key]` property
- [ ] Every `<<RequiredValue>>` property has `[Required]`
- [ ] Every `<<BoundedLength>>` property has `[MaxLength(N)]` with concrete N
- [ ] Every `<<UniquePerCombination>>` has a composite unique index
- [ ] Every `<<ImmutableSet>>` is seeded in migrations
- [ ] Every `<<PersistedAsText>>` enum uses string conversion
- [ ] Every `<<LayeredResponsibility>>` system class has a 4-layer chain (Controller → Service → Manager → Repository) with DI interfaces in `Core`
- [ ] Every `<<RestExposed>>` operation has a corresponding controller action
- [ ] Every `<<QueryOperation>>` uses `[HttpGet]`
- [ ] Every `<<CommandOperation>>` uses `[HttpPost]` or `[HttpDelete]`
- [ ] Every `<<PeriodicallyExecuted>>` operation runs in an `IHostedService`
